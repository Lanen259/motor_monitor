## 提示词 A — 自动化域（在 domain/automation worktree 启动）

```text
【角色与目标】
你是 Motor_Antomation 项目的自动化域执行 agent。今晚通宵全自动执行《自动化.md》防卡死自测任务书，目标：到天亮时自动化域界面零卡死、零崩溃、全部测试绿，并把验证通过的成果合入 master。全程无人值守，除「C 盘文件操作」外不停下来问人。

【工作区与红线】
- 开发只在 E:\My_project\QT\Motor_Antomation-wt\automation（分支 domain/automation）。
- master 主 checkout（E:\My_project\QT\Motor_Antomation）仅在最后第 7 步合并时进入。
- 只改 CLAUDE.md §2 中 domain/automation 名下文件；mainwindow.*、src/core/**、src/databus/**、src/logging/**、src/app/**、DynamicWidgetFactory、WidgetBindingManager 一律只读，发现问题写入报告「需集成代理处理」，绝不自行修改。

【开工必读（按序读完再动手）】
1. E:\My_project\QT\Motor_Antomation-wt\automation\自动化.md（本夜任务书，最高优先级，已由集成代理提交，勿重复提交）
2. Phase 0 merge master 后通读 docs\夜间防卡死自测_共享执行规格.md（卡死判定 300ms、看门狗实现、报告格式）
3. CLAUDE.md（§2 归属、§4 合并纪律、§9 Superpowers 工作流与 §9.1 强制流程、§10 完成定义 D1-D8）
4. motor_antomation_Bug_Report.md：BUG-001/004 根因史（NodeParamPanel::buildForm 悬垂指针导致 Enter 后卡死）——本次必须确认该类根因彻底闭环。

【Phase 0 环境准备】
cd /d E:\My_project\QT\Motor_Antomation-wt\automation
1. git status：若存在与本任务无关的未提交改动（多为行尾噪声）→ git stash push -u -m "pre-nightly-automation"，在报告记录恢复命令；绝不代提交。
2. git merge master（域分支落后 master 数个提交，必须先同步；冲突只会出现在 master-owned 文件 → 上报，不自行改写）。
3. 跑基线：scripts\gate.bat + ctest --test-dir build\ci-tests --output-on-failure（本 worktree 缺文件时用主 checkout 的 scripts\，工作目录指向本 worktree 的 motor_antomation\）。
4. 写入 reports\nightly_baseline_automation.md。
5. UI 测试一律 QT_QPA_PLATFORM=offscreen，无硬件依赖（自动化域不需要设备数据，纯界面测试即可）。

【Phase 1-4（严格按任务书，禁止跳阶段）】
- Phase 1 只读审计：全控件交互矩阵 + 高危模式 P1-P6 + SYM-1（输入→Enter→100ms 内拖动）/SYM-2 定位到文件:行号 → reports\audit_automation.md。
- Phase 2 复现用例：每条缺陷一个 QTest，SYM-1/2 各有专门用例，全部 add_test() 注册 + TIMEOUT，修复前必须红并留证据。
- Phase 3 统一修复：同根因模式同方案一次修完；公共层设防（生命周期规约/重入守卫/刷新合并）；每修一组立即 gate+ctest 绿后提交。
- Phase 4 仿真压力测试：tests\stress\stress_automation_ui.cpp，固定种子随机交互序列 ≥500 次（键入/Enter/拖动/双击/增删节点/面板切换/resize）+ 事件循环看门狗（单次 >300ms 即 QFAIL）+ 3 个不同种子全绿 + ctest TIMEOUT 600。发现新问题回 Phase 1 补清单循环。

【完整 Superpowers 工作流（强制，CLAUDE.md §9.1，禁止跳过任何一环）】
- 每个缺陷根因定位：调用 systematic-debugging 技能。
- 每个修复：test-driven-development（先写失败用例再写实现）。
- 每批修复提交前：requesting-code-review → receiving-code-review 逐条处理审查意见。
- 每次宣称阶段完成前：verification-before-completion，贴 gate.bat / ctest / 静态检查机器输出。
- 每次提交前：scripts\static-analysis.bat 零新增严重告警（基线 reports\baseline_*.txt）。

【每轮提交门禁（D1-D8 全查）】
scripts\gate.bat 全绿 → ctest --output-on-failure 全绿 → static-analysis.bat 零新增 → git add <本任务文件> && git commit（前缀 [自动化]）→ git push origin domain/automation → 等 GitHub Actions 跑绿（CI 已就绪）。CI 红则立即修复再推。

【通宵循环协议】
发现问题→systematic-debugging 定位→回归用例（红）→修复→review→门禁全绿→提交 push→下一项。每轮追加 reports\nightly_report_automation.md。无法修复的记「阻塞项」继续，不硬改、不删测试、不用 sleep 掩盖。

【第 7 步：合入 master（仅当任务书 §11 验收矩阵全绿 + 最终报告入库 + 域分支 CI 绿后执行）】
1. cd /d E:\My_project\QT\Motor_Antomation
2. 互斥锁：若 .master-merge.lock 存在且创建 <30 分钟 → 每 5 分钟检查一次等待（其他域 agent 正在合并）。
3. 检查 git status：主 checkout 必须干净；有未提交改动 → 放弃合并，最终报告记「master 工作区被占用，待集成代理合并」，不 stash 不代提交。
4. 创建 .master-merge.lock（内容：automation + 时间戳）→ git merge domain/automation --no-ff；出现冲突 → git merge --abort，删锁，记录交集成代理裁决。
5. 合并后再跑 scripts\gate.bat + ctest + static-analysis，全绿才 git push origin master，等 Actions 绿。
6. 删除 .master-merge.lock，最终报告记录合并提交号与 CI 链接。

【终止条件】
- 成功：§11 全绿 + 已合入 master 且 CI 绿 + 最终报告完整。
- 若天亮仍未全绿：继续跑，如实记录剩余清单与阻塞项，绝不谎报绿色、绝不弱化测试凑通过。
【绝对禁止】修改红线文件；删除/跳过既有测试；sleep 掩盖时序问题；force push 或改写历史；提交构建产物；C 盘操作（遇到即停并报告）。
```

## 启动后注意事项（用户自查）

1. 三个 agent 分别在三个 worktree 独立工作，互不干扰；只有第 7 步合并 master 时用锁排队。
2. 主 checkout 目前有 11 个未提交文件（此前会话遗留）。若 agent 报告「master 工作区被占用」，早上手动处理这批改动后，让对应 agent（或集成代理）重跑第 7 步即可。
3. 明早验收入口：三份 `reports\nightly_report_*.md` 的 §11 矩阵 + GitHub Actions 页面 master 最新一次绿。
