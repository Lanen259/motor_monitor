# 夜间防卡死自测 — 三域共享执行规格

> 文档版本：v1.0 ｜ 编制日期：2026-08-09 ｜ 编制角色：集成代理
> 用途：本文件是三个域分支夜间任务书（`自动化.md` / `波形.md` / `通讯.md`）引用的**共享规格**，定义三域统一的卡死判定标准、看门狗实现参考、报告格式与合并回 master 的规则。三个通宵 agent 各自独立运行，但机制必须一致，便于集成代理横向对比与统一集成。
> 背景：用户反馈"修一个 bug 又冒一个新 bug"，根因是逐症状打补丁 + 无回归测试。本轮以「系统审计 → 复现用例 → 按根因模式统一修复 → 仿真压力测试」替代单点修复。
> 总目标：**所有分支、所有界面不允许出现卡死与崩溃**；每一处修复必须有回归测试兜底，防止"修一个冒一个"。

## 2. 卡死判定标准与看门狗（三域统一）

### 2.1 判定标准

- **卡死**：UI 线程（主线程）事件循环单次事件处理耗时 > **300ms**，或连续事件处理间隙 > **300ms**（事件队列堆积）。
- **假死**：界面仍在重绘但对输入无响应超过 **500ms**。
- **崩溃**：进程退出码非 0、段错误、未捕获异常。
- 任何一条被触发即视为该用例/该轮压力测试**失败**，必须定位修复，不许绕过。

### 2.2 事件循环延迟看门狗（推荐实现，供三域参考）

在测试进程启动一个看门狗线程，周期性向 UI 线程 `postEvent` / `QMetaObject::invokeMethod` 投递"心跳任务"，记录投递时刻与执行时刻之差：

```cpp
// 伪代码要点（放入 tests/common/ 下共享头，例如 ui_watchdog.h）
class UiWatchdog : public QObject {
    Q_OBJECT
public:
    explicit UiWatchdog(int thresholdMs = 300);   // 阈值 300ms
    void start();   // 启动后台线程，每 50ms 向 UI 线程投心跳
    QStringList violations() const;               // 记录所有超时事件（含时间戳）
private:
    // 后台线程：每 50ms 记录 t0，invokeMethod(widget, Qt::QueuedConnection) 执行
    //           执行时取 t1 = now，若 t1 - t0 > thresholdMs 记一条 violation
};
```

要求：
1. 看门狗代码放在各域 `tests/common/ui_watchdog.h`（或等价位置），实现逻辑三域一致，便于对比。
2. 压力测试用例结束前检查 `violations()` 为空，否则 `QFAIL` 输出第一条超时记录及其操作上下文。
3. 看门狗自身不得引入 >5ms 的额外开销（心跳频率 20-50ms 之间自选）。

### 2.3 单用例防挂起

所有交互/压力测试在 `tests/CMakeLists.txt` 中设置：

```cmake
set_tests_properties(<测试名> PROPERTIES TIMEOUT 60)    # 普通交互用例
set_tests_properties(<压力测试名> PROPERTIES TIMEOUT 600) # 压力测试
```

ctest 超时即判失败，防止卡死用例把整夜流水线挂死。

## 3. 通用根因模式编号（三域共用词汇）

| 编号 | 模式 | 典型表现 |
|---|---|---|
| P1 | 悬垂指针 / use-after-free | 删除后访问、跨事件循环保存裸指针、removeRow/deleteLater 误用 |
| P2 | 事件重入 | 槽函数内弹模态框、setText 触发 editingFinished 再触发重建 |
| P3 | 信号槽循环 | A→B→A 无终止 emit 链 |
| P4 | 事件风暴 | mouseMove/resize/数据到达逐次触发全量重绘或重建 |
| P5 | UI 线程阻塞 | 槽函数内文件 IO、同步等待、大循环、阻塞式 exec |
| P6 | 动态增删无保护 | 迭代中删容器元素、拖动时后台事件修改同一容器 |

各域任务书可附加域专属编号（自动化无；波形 W1-W6；通讯 C1-C7），报告中引用编号须统一。

## 4. 四阶段执行协议（三域一致）

```
Phase 0 环境准备与基线（merge master、gate.bat、基线报告）
   ↓
Phase 1 只读审计 → 缺陷清单（含根因模式编号、文件:行号、触发序列）
   ↓
Phase 2 QTest 复现用例（修复前必须红，全部 add_test 注册）
   ↓
Phase 3 统一修复（同根因同方案，公共层设防，每步 gate+ctest 绿后提交）
   ↓
Phase 4 仿真压力测试（随机交互模糊测试 ×3 种子，看门狗全程在线）
   ↓ 发现问题回到 Phase 1 补清单（预期内循环）
收尾：最终报告 + push 域分支
```

- 每 Phase 结束必须产出阶段报告再继续，不许跳阶段。
- 所有 UI 测试 `QT_QPA_PLATFORM=offscreen`；无硬件依赖，数据走 `DeviceSimulator` 模拟管线。
- 完成定义叠加 `CLAUDE.md` §10 的 D1-D8；机器证据优先，不采信口头结论。

## 5. 报告格式（三域统一）

| 文件 | 内容 | 更新频率 |
|---|---|---|
| `reports/nightly_baseline_<域>.md` | Phase 0 基线：编译/测试结果、已知失败项 | 一次 |
| `reports/audit_<域>.md` | 缺陷清单：编号｜控件｜根因模式｜文件:行号｜触发序列｜风险｜状态 | Phase 1 产出，Phase 3 中逐条更新状态 |
| `reports/nightly_report_<域>.md` | 每轮循环追加：时间、修复内容、根因编号、测试证据、剩余清单、阻塞项 | 每轮追加 |

最终报告末尾必须附 §11 验收矩阵逐项结论与证据链接（ctest 输出、git 提交哈希）。

## 6. 职责边界（与 CLAUDE.md 一致，再强调）

1. 域 agent 只改本域名下文件；master-owned 红线文件（`mainwindow.*`、`src/core/**`、`src/databus/**`、`src/logging/**`、`src/app/**`、`DynamicWidgetFactory`、`WidgetBindingManager`）一律只读，发现问题写入报告「需集成代理处理」。
2. 新增 TopicId / 改 DataPoint / 接 mainwindow：域 agent 在报告中提出申请，由集成代理在 master 实施。
3. 域分支 → master 合并**只在主 checkout 由集成代理执行**，前置门禁 = 编译 + ctest 全绿 + 静态检查零新增严重告警 + 三域最终报告验收通过。
4. 手册同步：涉及 UI/功能变化的修复合入 master 后，由集成代理统一更新 `USER_MANUAL.md`（域分支内不改手册）。
5. 域分支在本夜结束前 `git merge master` 保持同步（Phase 0 已做一次；天亮合并前集成代理会再确认漂移 ≤2 轮）。

---

## 7. 天亮集成流程（集成代理执行）

1. 收集三份最终报告，核对各自 §11 验收矩阵。
2. 汇总三域「需集成代理处理」清单，评估是否涉及红线文件改动（如有，另行安排壳层任务）。
3. 依次在主 checkout 执行：`git merge domain/automation` → 集成验证 → `git merge domain/waveform` → 集成验证 → `git merge domain/comms` → 集成验证（门禁：gate.bat + ctest + 静态检查）。
4. 若某域验收未达标，不合并，把未达标项写回该域任务书继续下一轮。
5. 全部合入后：更新 `USER_MANUAL.md`（如有 UI 变化）、在 `motor_antomation_Bug_Report.md` 登记本夜闭环的缺陷、push master。

---

## 8. 全局禁止事项（三域通用）

1. 禁止跳过审计直接改代码；禁止逐症状打补丁。
2. 禁止删除 / 跳过 / 弱化既有测试换取绿灯。
3. 禁止用 `sleep` / `qWait` 掩盖时序问题（允许的等待只有：等待明确信号/状态变化的 `QSignalSpy::wait`）。
4. 禁止修改红线文件。
5. 禁止域分支自行合入 master。
6. 禁止提交构建产物（`build*/`）。
7. 禁止在未完成门禁（编译+ctest+静态）的情况下 push。
