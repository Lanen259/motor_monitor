# 单片机通讯协议注意事项（对接 MotorStudio 上位机）

> 用途：**单片机（下位机）开发参考**。按此文件实现/核对固件侧通讯，即可与上位机
> MotorStudio 联调。本文档依据上位机实际代码提取（`src/communication/*`），非想象协议。
>
> 配套文件：`vofa_comms.h` / `vofa_comms.c`（单片机侧可直接使用的模块）。

---

## 0. 一句话结论

| 方向 | 协议 | 说明 |
|---|---|---|
| 单片机 → 上位机 | **VOFA+ JustFloat** | 这才是上位机实际接线的协议（DeviceWorker + VofaParser） |
| 上位机 → 单片机 | 文本命令 `key=value` | 以 `\n` 或 `\r` 结尾；当前上位机尚无发送代码，用串口终端/VOFA+ 下发 |
| 串口 | 8N1，**默认 256000 波特**（可配置），无流控 | 见 §1 |
| 预留 | 二进制帧 `AA 55 …`（MotorProtocol） | 上位机**当前未启用**，作参考，见 §4 |

---

## 1. 串口参数（上位机 SerialTransport）

- 8 数据位 / 无校验 / 1 停止位 / 无流控。
- 波特率默认 **256000**；JSON 配置 `{"port":"COMx","baud":…}` 可改，或简单格式 `COMx:波特率`。
- 上位机读缓冲 64KB，`readyRead` 批量读取后整段喂给解析器。

⚠️ **单片机侧波特率必须与上位机一致**，否则收不到数据（最常见联调失败原因）。

---

## 2. 上行实时数据：VOFA+ JustFloat

- 每通道 **4 字节 float，小端序**（ARM Cortex-M 原生字节序，直接按地址拷贝即可，如
  `vofa_comms.c` 的 `Vofa_SendData`）。
- 上位机解析方式（`VofaParser::parseJustFloat`）：按**固定通道数**切帧，
  `帧长 = 通道数 × 4` 字节，**不识别帧尾** `00 00 80 7F`。
- 当前上位机通道数默认 **8**（`DeviceWorker` 未显式设置 → `VofaParser` 默认 8）。

⚠️ **帧尾与通道数必须匹配，二选一**：
- **方案 A（推荐直连上位机）**：每帧发固定 8 个 float（32 字节），**不加帧尾**，
  上位机默认 8 通道 → 直接对齐。
- **方案 B（标准 VOFA+）**：发 N 个数据 float + 帧尾 `00 00 80 7F`，上位机通道数须设
  **N+1**（帧尾被解析成一个 `+inf` 通道）。
- 若两者不匹配（如发了 8 个 float 又加帧尾，上位机按 8 通道切），**第二帧起数据永久错位**，波形全乱。

> `vofa_comms.h` 里 `VOFA_ENABLE_FRAME_TAIL` 控制是否加帧尾：直连上位机时置 0，连 VOFA+ 桌面软件时置 1。

---

## 3. 下行命令：文本 `key=value`

- 格式：`key=value`，以 `\n` 或 `\r` 结尾，例：`speed=1200\r\n`、`start=1\n`。
- 数值用十进制解析（`strtod`），整数字段自行取整。
- 建议在单片机侧实现的命令（对应你原 `vofa.c` 的 `vofa_Receive`）：
  `speed=` / `up_time=` / `down_time=` / `start=` / `stop=` / `set_iq=` / `set_id=` / `calib=`。
- 一条命令即一行，不要在同一行拼多条；解析器按行处理，抗半包/粘包。

⚠️ **当前上位机没有发送命令的代码**（`DeviceWorker` 只收不发）。联调下行时先用
VOFA+ 或串口终端手工下发命令验证单片机解析正确。

## 4. 预留：二进制帧协议 MotorProtocol（当前未启用，参考用）

> 上位机 `MotorProtocol.cpp` 已实现编解码，`DataManager` 也能处理，但**未接入**
> `DeviceWorker` 的接收路径（它用的是 JustFloat）。如需启用，以本节为准。

### 4.1 帧结构

```
| AA | 55 | DevID(1B) | Cmd(1B) | Len(2B LE) | Payload(LenB) | CRC16(2B LE) | 0D | 0A |
| 同步头        | header 6 字节                              | 校验            | 帧尾 |
```

- CRC16 计算范围：从 `AA` 起，共 **6 + Len** 字节（header + payload）。
- CRC16 算法：**CRC-16/XMODEM** — 多项式 `0x1021`，初值 `0x0000`，
  输入/输出**不反转**、结果**无异或**；追加时**低字节在前**。

```c
uint16_t crc16_xmodem(const uint8_t* d, size_t n) {
    uint16_t crc = 0x0000;
    for (size_t i = 0; i < n; i++) {
        crc ^= (uint16_t)d[i] << 8;
        for (int j = 0; j < 8; j++)
            crc = (crc & 0x8000) ? (crc << 1) ^ 0x1021 : (crc << 1);
    }
    return crc;
}
```

**测试向量**（用来验证单片机实现是否正确）：

| 帧内容（不含 CRC/帧尾） | CRC16 |
|---|---|
| `AA 55 01 03 00 00`（DevID=01, CmdWrite, 空载荷） | `0x7EAB` → 追加 `AB 7E` |
| `AA 55 01 07 00 00`（Reset） | `0xA26B` → 追加 `6B A2` |
| `AA 55 01 01 32 00`（DataUpload, Len=50） | `0x733C` → 追加 `3C 73` |

### 4.2 命令码（MotorCommand）

| 码 | 命令 | 方向 | 含义 |
|---|---|---|---|
| 0x01 | DataUpload | 设备→主机 | 实时数据上传 |
| 0x02 | CmdRead | 主机→设备 | 读参数 |
| 0x03 | CmdWrite | 主机→设备 | 写参数 |
| 0x04 | Ack | 设备→主机 | 应答 |
| 0x05 | Nack | 设备→主机 | 否定应答 |
| 0x06 | Heartbeat | 设备→主机 | 心跳 |
| 0x07 | Reset | 主机→设备 | 复位 |

### 4.3 DataUpload 载荷（MotorDataPayload，字段顺序不能改）

| 字段 | 类型 | 字节 |
|---|---|---|
| timestamp | uint32 LE | 4 |
| ia, ib, ic, id, iq | float LE ×5 | 20 |
| speed, position | float LE ×2 | 8 |
| busVoltage, busCurrent, temperature | float LE ×3 | 12 |
| fault | uint16 LE | 2 |

⚠️ **已知不一致**：上位机注释声称 payload 为 50 字节，但 packed 后实际只有 **46 字节**
（1×uint32 + 10×float + 1×uint16）。启用该协议前需两端统一（改上位机或改载荷定义）。

### 4.4 上位机解析行为（便于单片机侧理解容错）

- 无同步头字节会被丢弃；乱码时向前扫描 `AA 55` 重新同步。
- CRC 错误仍会产出帧，但 `crcValid=false`；帧尾 `0D 0A` 校验失败会计入 frameErrors。
- 单片机侧建议：CRC 校验失败直接丢弃并等待下一个 `AA 55`。

## 5. 单片机实现注意事项（避坑）

- **字节序**：所有多字节一律小端；float 直接按地址写即可。
- **发送节奏**：JustFloat 用控制环/定时器**周期性**发送，不要在中断里零散拼帧；
  每帧字节数固定，便于上位机按通道数对齐。
- **DMA 发送**：若用 DMA，发送回调内务必先拷贝到独立缓冲再触发 DMA（防止下一帧覆盖
  未发完的缓冲），或等待上一帧发送完成。见 `vofa_comms.h` 的 `Vofa_Init` 注释。
- **接收**：串口中断/DMA 空闲收到字节后整段喂给解析器；解析器内部按行缓冲，处理半包/粘包。
- **上电即发**：上位机连接后即开始收，单片机不必等待握手，上电即可按周期上传。
- **帧率与带宽**：256000 波特 ≈ 25.6KB/s。每帧 32 字节（8 通道）时理论上限约 800 帧/s，
  实际留 3~5 倍余量，建议 ≤ 200 帧/s。

---

## 6. 联调检查清单（Checklist）

- [ ] 单片机与上位机**波特率一致**（默认 256000），8N1、无流控。
- [ ] JustFloat **通道数一致**；帧尾开关与上位机通道数匹配（§2 方案 A/B 二选一）。
- [ ] 先单独用 **VOFA+ 桌面软件**验证单片机波形正确（帧尾标准），再连上位机。
- [ ] 用串口终端下发 `speed=1000\n` 等命令，确认单片机解析回调触发。
- [ ] 若启用二进制帧协议，用 §4.1 测试向量验证 CRC 实现。
